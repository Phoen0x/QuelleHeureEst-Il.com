## Recherche et décision

[Advisory RustSec](https://rustsec.org/advisories/RUSTSEC-2026-0486.html), GHSA-jh2m-fhpj-3vr7 : fonctions xattr Buffer affectées à partir de 1.0.0, corrigées dès 1.1.6 ; 0.38 non affectée. Avec un tampon de longueur nulle, la taille renvoyée par le système était utilisée pour déclarer initialisée une région non écrite. L'avis est classé **unsound**, pas une nouvelle vulnérabilité classée dans le tableau cargo-audit.

[Correctif officiel](https://github.com/bytecodealliance/rustix/commit/8e6aaa6713d2bb64b1fdd8c472e3a32a10a76d70) et [comparaison 1.1.5→1.1.6](https://github.com/bytecodealliance/rustix/compare/v1.1.5...v1.1.6) examinés avant modification. La version publiée 1.1.6 correspond à `4a563ad698b2c20ff848515821023d2265a788d0`, contient les six branches de traitement des tampons nuls et les six API `*_query`. Le fichier réellement résolu `src/fs/xattr.rs` a le blob **c948edee88c72dd6e190f7cbd19dabbdb20b3172**, identique au fichier du correctif officiel.

Crates.io : version1.1.6 publiée le 27 octobre 2026, non retirée au relevé ; checksum **e5e76742e5294153d4dde1207dbec5bdd81eef6fabdc0d2118babadabfd858aa**, vérifié contre l'API, le verrou et l'archive téléchargée. Origine registry crates.io. Licence déclarée `Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT`, inchangée ; aucun audit de licence complet ni politique modifiée.

`tempfile 3.27.0` déclare rustix `^1.1.4`, feature fs, sur Unix/WASI. La stratégie A, mise à jour transitive du verrou, est retenue. Mettre à jour tempfile (B) serait inutile ; un rétroport local (C) augmenterait maintenance et provenance sans nécessité ; suppression ou ignore (D) exclus. Aucune dépendance directe ajoutée.

La comparaison amont comporte **18 commits et 36 fichiers**, pas seulement le correctif xattr. Le minimum bitflags passe 2.4.0→2.9.2 (le verrou contient déjà 2.13.2) ; les crates rustc-std-workspace optionnelles passent 1.0.0→1.0.1 et l'arête bitflags/rustc-dep-of-std est retirée de cette feature spéciale non activée. Le MSRV déclaré demeure **1.65**, non testé avec ce compilateur exact. Le minimum libc de développement augmente, sans changement de la résolution applicative. La plage windows-sys reste `>=0.52,<0.62` et ses fonctionnalités Foundation/WinSock sont conservées.

Autres changements amont : correctifs Android de compilation et activation sendfile, UID/GID32 sur certaines architectures Linux32bits, RELATIME/inotify et IPv6, fallocate/termios et buffers SCM_RIGHTS sur Apple, conditions FreeBSD/DragonFly et flags termios. Les variantes optionnelles restent représentées par les versions/sources historiques archivées ; elles ne sont pas réactivées. Ces changements sont inclus dans la publication officielle, **pas tous testés nativement ici**.

Issues examinées : [#1693](https://github.com/bytecodealliance/rustix/issues/1693), [#1711](https://github.com/bytecodealliance/rustix/pull/1711) (commentaire confirmant la résolution en 1.1.6), [#1721](https://github.com/bytecodealliance/rustix/issues/1721) (test amont macOS signalant un attribut absent, fermé, sans explication dans les commentaires accessibles). Cet échec n'est ni caché ni transformé en preuve de régression applicative. La sonde locale utilise un attribut synthétique valide `user.qh_safe`. Une requête de recherche GitHub n'a pas fourni de contenu exploitable ; la collection récente d'issues a permis les lectures ciblées. Pas de recherche communautaire générale prétendument exhaustive.

## Résolution exacte et exposition

Commande initiale depuis la racine : `cargo update -p rustix --precise 1.1.6`, sans --locked comme requis. Cargo a réorienté six arêtes Windows (dirs-sys, errno, rustix, tempfile, winapi-util, winreg). Ces écarts ne sont pas nécessaires : les plages acceptent les versions antérieures. Tous sont restaurés à l'octet depuis l'original ; `cargo metadata --locked` accepte le résultat. La première résolution est conservée temporairement, pas confondue avec le candidat final.

**Le seul diff Cargo.lock final est la version rustix 1.1.5→1.1.6 et son checksum.**501 paquets avant/après ; tempfile 3.27.0, toutes les autres identités, arêtes et fonctionnalités inchangées. Graphes par défaut 499→499 et toutes fonctionnalités 501→501 : comparaison intégrale après renommage de cette seule identité. rustix conserve alloc/default/fs/std. Les verrous et graphes historiques sont archivés, jamais réécrits.

Inversion toutes cibles : rustix ← tempfile 3.27.0 ← native-tls 0.2.18 ← hyper-tls/tokio-native-tls/reqwest 0.12.28 ← application. **Ce chemin est conditionné à macOS dans native-tls.** Les inversions Linux et Android ne contiennent pas rustix actif ; sa présence dans Cargo.lock et metadata toutes cibles n'est pas une preuve de chargement dans les binaires Linux/Android. Le graphe macOS le confirme, sans exécution native. Tauri 2.11, Tokio 1.54.1, GLib et ses deux correctifs, HTTP/2 et SQLite 3.54.1/sys0.39.1/rusqlite0.41.1 restent inchangés.
