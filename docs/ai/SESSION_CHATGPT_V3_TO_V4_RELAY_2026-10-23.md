Distinguer observations **indépendantes** (diff Git, logs CI), validations **rapportées seulement par Codex**, tests **non effectués**, scanners partiellement verts, et résultat de la véritable commande. ### Étude Codex non destructive déjà réalisée — base pour V4

Une mission **en lecture seule**, **sans commit**, précédant le rétroport GLib a identifié trois familles : GLib/GTK + macros (2), URLPattern/UNIC (5), PEM (1). Rust 1.99.1, cargo-audit 0.22.2, Debian 13.6 ; audit 0 vulnérabilité + 8 avertissements ; investigations de graphes et fonctionnalités. Résultats rapportés par Codex, non revalidés intégralement dans un environnement indépendant.

- **GLib** : rétroport minimal maintenant réalisé et audité, donc **ne pas le recommencer**.
- **Cinq UNIC** : expérience locale `cargo update -p tauri-utils --precise 2.10.2` **sans changer Tauri 2.11.6** ; `tauri-utils 2.10.2` prend `urlpattern 0.6` et **ICU** au lieu d'UNIC, disparition des 5 avis dans cette résolution ; audit expérimental **0 vulnérabilité + 3 warnings, exit 1**. **Ce scénario n'est PAS publié** : `Cargo.lock` passerait de **504 à 509 entrées**, **13 anciennes identités retirées et 18 ajoutées**, impact sur compression/HTML/JSON/détection de fichiers et **MSRV tauri-utils 1.77.2 → 1.90**. Une migration doit archiver les 13 identités anciennes, conserver les représentations historiques, justifier chaque changement, préserver tous les profils et fonctionnalité.
- **Divergences Unicode constatées** : harnais 27 cas URL → **24 mêmes résultats, 3 différents** (notamment caractères U+11F02, U+11F00, U+1C89, et traitement de noms partiels) ; **4 propriétés** contrôlées ; `ID_Start` **n'est pas** `XID_Start` (exemple U+309B). Risque pour sémantique de motifs **RemoteUrlPattern / ACL d'URL distantes Tauri**, même si aucun usage ACL distant explicite n'a été trouvé dans les JSON examinés. Ne pas qualifier la migration pour publication par un simple `cargo check` Linux ; créer matrice de non-régression des acceptations ET refus de sécurité avant changement.
- **Macros** : fork proc-macro-error2 2.0.1 en essai local : alias simple **échoue** ; imports adaptatifs permettent `cargo check --lib` sur glib-macros et gtk3-macros, mais future-incompat et suites UI/diagnostics non validées. Alternatives manyhow ou proc-macro2-diagnostics ; pas de migration autorisée.
- **PEM** : 15 comparaisons synthétiques, 13 identiques après normalisation, 2 extensions reconnues par nouvel API ; conserver `rustls-pemfile =1.0.4` optionnel, alternative `rustls-pki-types` déjà présente dans le verrou. **Aucune suppression** pour éteindre artificiellement RustSec ; avis du lockfile persisterait.
- **Conclusion de l'étude** : aucune voie prouvée actuellement vers **0 avertissement** sans enjeu de compatibilité/conservation ou reconnaissance RustSec. **V4 doit reprendre la qualification du scénario Unicode de façon ciblée**, **ne pas publier** une mise à jour tauri-utils sur la seule base de l'expérience.

## 7. Environnement, preuves et limites de reproductibilité

- Session Codex utilisée : **Debian 13.6 x86_64**, Rust/Cargo **1.99.1**, Node **24.19.0**, pnpm **8.15.9**, CLI Tauri **2.11.2**, dépendances Tauri **2.11.6**. Les bibliothèques natives Linux ont été reconstruites en chemin privé depuis des paquets Debian vérifiés ; guide `docs/development/linux-environment-20261022.md` sur #183. Ne pas supposer que `apt`, GTK, WebKit ou Java/Android sont prêts sur chaque runner.
- Une validation **`cargo metadata`** n'est pas une compilation ; un build Linux n'est pas un APK Android ; le test CLI Tauri `--debug --no-bundle` n'est ni installation ni exécution GUI ; des tests HTTP avec serveurs simulés ne prouvent pas TLS réel ou résistance universelle à HTTP/2 malveillant.
- Les assertions de Codex **53/59/71 cas Node**, **764 tests amont braces**, **24 000 comparaisons** sont des périodes différentes : ne pas les additionner, ni attribuer à une CI nouvelle. Au HEAD GLib, CI fait **22 tests Node** et **8 tests Rust debug**. Les jobs security en `continue-on-error` peuvent mentir par leur conclusion affichée.
- Les liens directs de logs et les artefacts GitHub Actions peuvent expirer, d'où les rapports `docs/reports`, archives `docs/history`, scripts et inventaires SHA dans la PR #183. Une nouvelle conversation doit **rejouer/revoir les preuves pertinentes**, pas prétendre avoir consulté des logs périmés.
- Un gel/freeze de l'interface ChatGPT sur « analyse des logs » côté application a motivé le passage volontaire de **V3 à V4**. **La dernière opération V3 est terminée et ses écritures ont été vérifiées** : revue GLib créée sur #187, journal #186 modifié, backlog et roadmap #187 modifiés, descriptions #186/#187 mises à jour. Le gel de l'application **n'a pas empêché** la confirmation de ces commits sur GitHub. Ce relais est ajouté **après** ces validations, distinct des actes de code Codex.
